# Experimental discovery foundation (AL-EXP-01, slice 1)

Status: implemented for the approved slice 1 scope (BL01–BL06 on synthetic NROM fixtures). Acceptance: `QA/al-exp-01.cjs`,
part of the full regression. Not in this slice: banked or CHR-RAM fixtures, the worker experiment job kind (BL08), any
commercial-ROM experiment, pointer, collision and compression discovery (BL07, BL10, BL11), a second emulator (BL12).
Those need separate approval.

## What it does

Forge can find an unknown 2×2 metatile table in a cartridge it has never seen, without being told where the table is
or how it is laid out:

1. **Observe.** The cartridge runs a training input in an isolated copy of the editor. Two cold runs and two runs
   restored from a checkpoint must agree exactly, with a bus trace recording which PRG bytes the game read as data.
2. **Propose.** The finder searches the cartridge for tables that explain the observed screens. It considers
   interleaved records and split arrays, both quadrant orders, every stride up to 256 and four grid alignments. It
   ranks candidates by how much of the screens they explain and how much of them the game actually read. Record 0's
   position comes from the operands of the instructions that read the table.
3. **Test.** For each leading candidate, one tile byte of one record is changed in a private copy of the cartridge,
   and the finder predicts exactly which nametable cells change, to what, in every capture. The prediction is checked
   against the replay. A same-value control and an unrelated-byte control must show no effect. The surviving
   candidate's palette array is tested the same way.
4. **Freeze.** The surviving candidate becomes a sealed, hashed `NESForgeCandidateDefinition`: data only, status
   `candidate`.
5. **Withheld input.** Only now does the withheld input run. Its screen is reconstructed from the frozen definition,
   cell by cell, with each cell marked observed, interior, resolved by palette, ambiguous, extended or unknown, and
   attribute bits stated only where they are known.

An independent oracle, outside the editor, then judges the definition and the reconstruction against the fixture
generator's own data.

## Isolation: a second copy of the same build

Experiments never run in the editor's own emulator. The emulator is not one file: renderer, header parser, frame
loop, CPU bus and mapper behaviour are assembled from overrides in about ten files, so a copy of one file would be a
different engine. The sandbox is instead a second instance of the whole standalone document:

- **The document.** The host rebuilds the document from the embedded shell and its own script text. It is
  byte-identical to `NES_Forge.html`, and the acceptance suite checks that its SHA-256 equals the file's.
- **The iframe.** It is loaded with `sandbox="allow-scripts"`: an opaque origin with no access to the editor's
  IndexedDB, localStorage, document or project.
- **Messages.** The host and agent exchange `postMessage` with a per-session nonce and source checks. The agent
  accepts four commands (`hello`, `run`, `cancel`, `release`) and evaluates nothing it receives.
- **Running a trial.** The agent loads the trial's cartridge with the emulator's own loader. It drives frames
  directly, with the trial's input as the joypad state. Checkpoints are the frame history's own owned checkpoints,
  bound to the cartridge's SHA-256. It runs in chunks of about 16 ms.
- **Cancellation.** A soft cancel stops at the next chunk. If the agent does not stop, the host removes the iframe.
- **Restrictions.** NROM only in this slice. Experiments run only on cartridges carrying the synthetic-fixture marker
  (`NESFORGE-SYNTHETIC/1` at the start of the last 256 bytes of PRG).

**Process model.** In the Chromium used by the acceptance suite, the sandboxed iframe shares the editor's renderer
process, so the sandbox's start-up (about 1 s) holds the editor's thread for about 0.5–0.7 s once per experiment.
Trials and the finder search yield, so the editor stays responsive between them. The suite measures this every run.

## Observation (BL03)

The observer wraps the sandbox copy's `cpuStepRaw`, `cpuRead`, `cpuWrite` and `ppuBusWrite`. It only records what
passes through and never reads the bus itself, so it cannot trigger I/O side effects.

- **Access roles.** Each PRG byte gets role bits: opcode fetch, operand fetch, data read, vector read, other. A byte
  never touched keeps 0, which means unknown.
- **Ordered log.** PRG data reads, vector reads, PPU writes (with the mirrored nametable or palette address they land
  on) and watched RAM writes go to an ordered log with a cap.
- **Truncation.** Past the cap the trace is marked truncated and incomplete, and receipts say that absence is not
  evidence.
- **Hangs.** A program stuck in a loop with no interrupt for 60 frames is stopped and classified as a timeout.

## Runs, receipts and evidence (BL04, BL05)

**Variants.** Every variant is a new copy of the cartridge with its mutations applied. The base is never written, and
its SHA-256 is re-checked after every trial.

**Comparison.** Each trial is compared with the plan's reference cold baseline:
- per channel: CPU registers, RAM, nametables, palette, OAM, CHR-RAM, pixels;
- the first diverging frame;
- the first diverging traced bus event.

**Outcomes.** One of `no_effect_observed`, `effect_observed`, `target_not_reached`, `crash`, `timeout`, `cancelled`,
`unsupported`, `inconclusive` or `invalid`.

**Receipts** (`NESForgeExperimentReceipt` v1) carry:
- plan, input, base and variant identities;
- checkpoint, outcome and channels;
- capture digests and payload references;
- trace summary, limits and limitations;
- a verification block whose `independent` field must be `false`.

They are sealed with the SHA-256 of their canonical body. Timing is kept outside the hash.

**The evidence store:**
- stores each payload once per exact SHA-256;
- keeps one causal edge per trial;
- re-verifies receipts and candidates when they are added or imported;
- exports metadata only: hashes, offsets, counts and outcomes. Cartridge byte values appear only for synthetic
  fixtures, and there are no file names or paths.

**Separate from the library.** It never writes to the resource library, a project or a cartridge, and the library's
intake paths refuse candidate definitions.

## Verification levels

| Level | What it shows | Where |
|---|---|---|
| Same-engine repeatability | The engine is deterministic for this input | Repeated baselines (cold and restored); receipts say `same-engine repeatability` |
| Predicted interventions | A candidate's predicted effect occurs and decoys' do not | Discovery step 3, same engine |
| Independent oracle | The definition and reconstruction match the generator's data | `QA/fixtures/al-exp-01/oracle.cjs`, outside the editor; no emulator, no shared code |
| Review | A person accepts a candidate | Not implemented; nothing is promoted |

The oracle is independent of the discovery code, not of its author. A second emulator is later scope. The acceptance
suite shows the difference: a definition shifted by one record reconstructs identically every time on the same engine,
and the oracle rejects it.

## Fixtures and the withheld seeds

`QA/fixtures/al-exp-01/` holds:
- the deterministic generator, with its own small 6502 assembler (not Forge's);
- the committed cartridges;
- their truth files;
- the oracle.

Twelve seeds are pinned in `seeds.json`:
- seven development seeds, used while the discovery code was built;
- one acceptance seed and four generalization seeds, declared before the code was finished and never run until the
  acceptance run.

The discovery code was frozen at `6d6022e`. Later changes to it were scheduling only:
- the finder's search became a generator that can yield;
- the agent's chunks were shortened;
- refused trials no longer count as repeats.

## Reproduce

```bash
node QA/fixtures/al-exp-01/generate.cjs --check
```

```bash
node QA/al-exp-01.cjs NES_Forge.html /tmp/al-exp-01.json /tmp/al-exp-01-shots
```

In the editor: CODE → RE / DISASM, open the analysis workspace, then **Experimental discovery · synthetic
demonstration** → **Run demonstration**.
