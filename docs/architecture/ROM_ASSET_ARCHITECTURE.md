# NES Forge: universal ROM workspace and agent architecture

**Status:** agreed architecture / incremental implementation, 2026-11-18. This document is not a claim of general native editing or 800 fully supported games.

## Guiding principles

1. **One workspace per ROM identity.** Use SHA-256 of complete input ROM, header and mapper/submapper; display title is a user-facing label only. Different revisions must not share offsets or provenance automatically.
2. **Same categories for every ROM.** World/Scenes; Graphics/CHR/Palettes; Animation/Sprites; Audio; Collision/Physics; AI/Behavior; Code/Runtime; Build/Patches. A category exists even when no resources are identified.
3. **Many recovery routes, one inventory.** Physical bank extraction, existing `NativeResourceProject` adapters, `GameRENative.inspect` investigated source catalogs, native audio driver profiles and emulator traces produce evidence into one source-scoped resource catalog. Missing an adapter must not suppress other supported recovery paths.
4. **No parallel competing asset stores.** Native/editor working copies must use Forge's existing ProjectStore, Resources, and domain codecs. Sidecar inventories are evidence and pointers, not another authoring database.
5. **Observed != rebuilt.** Separate raw extraction, record identification, decoding, editable copies, emulation, independently verified parity, and native writeback. Never turn a source-record count into a fully reconstructed scene count.
6. **No commercial asset distribution.** Users load their own ROMs locally. Keep ROMs, original PRG/CHR data, captures, decoded scenes, private audio and projects containing copyrighted content out of public GitHub and test fixtures. Public format support and research annotations are allowed subject to applicable licenses.
7. **Offline first.** `NES_Forge.html` runs without Qwen, a hosted API, a wallet, or blockchain access. Agents operate externally during development; wallet import may be optional later.

## Resource lineage

A resource record should carry: `rom_sha256`, `mapper`, `profile_id` when exact-match verified, `category`, `kind`, `source_bank`, `cpu_address/file_offset` if grounded, `discovery_tool`, `tool_version`, `evidence_state`, source/derived content hashes, and explicit unresolved fields. Exact source offsets are critical for the eventual native writer, but do not assume static PRG offsets reflect mapper state during execution.

Proposed state progression: **unverified → extracted → catalogued → decoded → editable → roundtrip_verified**. `runtime_observed` and `pixel_parity_verified` are orthogonal properties, not automatic upgrades. Agents cannot upgrade a state based solely on prose generated by a model.

## Six logical roles, one Qwen instance

| Role | Scope | Evidence needed |
|---|---|---|
| Extraction | ROM header, bank mapping, raw sources | SHA-256, independent bytes, mapper trace |
| Graphics & World | CHR, palettes, scenes, sprites, poses | source offsets, decoded frames, original pixels |
| Audio | APU, songs/SFX, timing | driver trace, reconstructed audio parity |
| Collision & Physics | terrain solidity, hitboxes, collision routines | RAM/CPU trace and runtime tests |
| AI & Behavior | state machines, enemies, triggers | control-flow and observed behavior tests |
| QA & Validation | regression gates, edit/build, evidence | independently repeated acceptance results |

Agent Lab v0.3 implements deterministic extraction, some investigated catalogs and optional audio/runtime observations, with **a single Qwen suggestion pass**, not autonomous execution of these six LLM roles. Their future task contracts must restrict tool access, use sequential inference on an 8 GB VRAM machine, and require owner approval for code changes.

## Specific integration gap closed in sidecar v0.3

Previous Agent Lab checked only `NativeResourceProject` and labelled exact Ninja Gaiden ROMs unsupported if that adapter was absent. `GameRENative.inspect` has separate, source-scoped *read-only* catalogs for investigated Ninja Gaiden and Zelda II revisions. `tools/agent-lab/tools/forge_investigated.cjs` queries that catalog and stores it privately, while the published-compatible summary contains only counts/states. It does **not** export a complete edited ROM or decode every level to working scenes.

## Gates before claims of generalized 800-game compatibility

One test per title/revision is not equivalent to one decoder per title. Track per-domain coverage and failure classes; aggregate reusable mapper/codec research where valid. Require deterministic synthetic fixtures, owner-supplied local ROM validation, visual/audio parity, editable persistence, and a demonstrated native rebuild before advertising complete support. AI is a research assistant; deterministic decoders and tests must remain the product.
