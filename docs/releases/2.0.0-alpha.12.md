# NES Forge 2.0.0-alpha.12 · Integrated Review 6

Development alpha. Open `nes-forge.html` (or `NES_Forge.html`) in Chrome or Edge. It still works offline, and projects saved by alpha.11 open unchanged.

## Highlights

### Studio layout
- **One bar:** Open… · New · Save · Save As… · **Library / Edit / Play / Build** · project · VR / AR · Learn · Tools · Classic layout. It replaces four rows of duplicate entry points.
- **Library** shows every asset in the project with a thumbnail and a badge:

  | Badge | Meaning |
  |---|---|
  | **BUILD** | Builds into your game |
  | **ROM** | A native writer encodes it into the original ROM |
  | **COPY** | Saved with the project, but a native build refuses it |
  | **REF** | Read-only evidence |

  You can search and filter, see what each asset uses and what uses it, open it in its editor, and get native-writer suggestions with shared-asset warnings. Example: Mike Tyson's graphics can be edited through the CHR bank 11 view, which also changes Piston Honda.
- **Build** checks the project and names the exact asset behind a refused build, plus every change since the last buildable state.
- **Play** builds and runs the project.
- **Tools** keeps every original control, and **Classic layout** shows the old toolbar rows again. Nothing was removed.
- **Keyboard:** Ctrl+K opens a command palette; Alt+1–4 switch modes.
- **Phone width:** the layout fits without sideways scrolling.

### VR / AR (spatial view)
- The running game is a floating screen with the project's stages (Worlds) or Scenes arranged around it.
- Desktop preview: drag to look, wheel to move, click to select, Shift+drag to move a screen. The keyboard plays the game.
- WebXR (`immersive-vr` / `immersive-ar`) on supporting devices. Controllers and tracked hands press NES buttons and grab screens.

### One command core
- `Forge.commands` is one set of named operations behind every interface: desktop, touch, keyboard palette, controller, XR, command line and agents. It covers projects, extraction packs, ROM intake/import, resources with editability, native writers, build, emulator and input.
- `node tools/forge-cli.cjs` runs the same commands from a terminal or script.

### Measured ROM audit
- `tools/audit/rom_audit.cjs` imports each exact ROM through the command core and measures what's visible, editable, saved/reopened and rebuildable.
- [Report for the 20-revision corpus](../audit/2026-11-19/AUDIT.md): every unchanged import rebuilds its original ROM byte-for-byte. The backlog ranks the missing decoders and writers by how many ROMs each one blocks.

### Extraction packs
- `tools/check_extraction_pack.cjs` runs the editor's own intake on a pack before anyone uses it, and [docs/extraction/PACK_FORMAT.md](../extraction/PACK_FORMAT.md) states the rules.
- ZIP errors now say which limit was hit, for example "ZIP has 2,265 files; NES Forge opens at most 2,048".
- Mario 1/2/3 extraction packs, their object placements and their audit reports open in the intake.

### Project health
- CI now runs on `main` and every pull request: byte-for-byte build, launch entries, build identity, public profile, Agent Lab tests and the repository QA suite.
- One build identity: `release-info.js` is the single source, and a check fails if any label disagrees with it.
- Release migration: recipes recorded with alpha.11 replay on alpha.12 with a foundation-only migration, and that is checked automatically.

## Verification

- Release QA: 42 of 42 suites pass on this build. That covers the repository suites, the 18 extraction packs, the 16-cartridge corpus and the real-browser check at 1440×900 and at 390×844 with touch. The browser check includes the studio layout and the spatial preview.
- Extended native corpus: 20 of 20 ROM revisions pass.
- Summary: [reviews/integrated-review-6/Public_Verification.json](../../reviews/integrated-review-6/Public_Verification.json). It holds counts only; private inputs are not published.
- Regression fixtures: `QA/r/game.nes` and one pinned build hash were rebuilt. Generated ROMs embed the project's `foundation` (the release version). Only those 13 bytes changed; the embedded project is otherwise identical to alpha.11's.

## Known limits (unchanged by this alpha)

- Native writers stay title-specific and bounded. Most games have no CHR, palette, collision, sprite or audio writer yet; see the audit backlog.
- Immersive VR/AR sessions are untested on headset hardware. The desktop preview is tested.
- Generated games build for mapper 0 (NROM) only. The larger cartridge profile and the Castlevania → Contra crossover slice are planned for alpha.13, along with the Punch-Out pose-layout writer.
