**NES Forge 1.6.7 — Architecture Convergence**

Audit and implementation plan · 14 September 2026

**Status: audit complete; implementation not started.** The current 1.6.6 application, source layers, tests, examples, and release ZIP have not been edited. This plan applies the user's course-correction instructions to the actual supplied implementation. It does not claim access to a separate unseen audit document.

**Decision.** Freeze 1.6.6 as the behavioral reference and use 1.6.7 to consolidate project lifecycle, asset references, build orchestration, and documentation. Keep the standalone HTML and existing editor tabs. Preserve the single-room Player/Target implementation as a bounded proof of concept. No new gameplay, mapper support, world execution, audio compilation, reverse-engineering engine, or live editing is included.

The exception to behavior preservation is the explicitly requested cleanup: remove production example data, start blank, replace stale messaging, and reject data-losing or malformed compatibility paths. The storage races and world-reference loss below also belong in this release because they directly affect the new project-lifecycle boundary. Each exception requires a named regression case and a documented before/after result.

**3. Behavioral boundaries to freeze**

Preserve the three exact source guards in `tests/preserved-source.json`: emulator core/renderer, provenance capture, and Save As/scene-aware CHR. Keep their hashes. Also freeze the existing single-room engine emitter and the world/asset/gameplay wire codecs with new byte/behavior guards before extraction. Protect the surrounding entrypoints with behavioral tests because not every load/run function is inside the current source guard.

| Boundary | Contract |
| --- | --- |
| Editing and authoring | Existing tabs, placement, facing/origins, animations, contact boxes/events, worlds, metatiles, camera data, collision properties, tracker data, and optional assembly remain editable and persistent. No wizard or replacement authoring flow. |
| Project replacement and history | New Project and clean Forge-ROM opening remain validated, undoable replacements. Ordinary undo/redo retains its existing playback behavior. Replacement pauses stale runtime and detaches the browser save identity. |
| ROM actions | Build & Run builds the current project. Run Original plays preserved original bytes. Build failure clears stale output. Clean Forge-ROM opening and append/capture import remain distinct operations. |
| Capture/CHR/Save As | Keep exact capture provenance and merge/bake paths, palette behavior, file-picker gesture/context handling, cancellation, and downloaded-byte behavior. No frame-loop or capture rewrite. |
| Generated gameplay | Existing fixed 256×240 single-room Player/optional Target slice only. Same movement, collision, binding, animation, attack/reaction, and resource-limit behavior. |
| World/audio/RE | Preserve authored world data and tracker data without claiming they are executed. Imported mapper support does not imply mapper-backed building. Keep the experimental RE branch separate. |
| Synchronization | Preserve existing linked-view whole-project BroadcastChannel synchronization. It remains separate from future runtime synchronization. |

**4. Target internal services for 1.6.7**

Use one composition root with a stable internal namespace such as `Forge.services`. The names below describe ownership, not a requirement to introduce classes or a framework. Keep legacy global APIs as thin, documented compatibility entrypoints where tests or existing UI require them.

| Service | Owns in 1.6.7 | Initial extraction seam | Deliberately deferred |
| --- | --- | --- | --- |
| **ProjectStore** | Blank construction; envelope validation/migrations; active-scene commit; detached project snapshots; atomic replace/history boundary; recovery lifecycle; asynchronous save identity/revision guards. | `saveCurrentScene`, `projectData`, `db_deserializeState`, browser save/recovery, private `replaceProject()` in `project166.js`. | Rewriting every editor field handler or the entire undo engine; changing Save As internals. |
| **AssetRegistry** | Reference lookup and validation for scenes, worlds/rooms/markers, metasprites, animations and entities; existing ID normalization; build reference maps. | Current `Forge163`/`Forge164` lookup/ensure/validation functions and world source references. | New persistent runtime IDs, asset database, blanket remapping of metatile/tile indices, immutable editor rewrite. |
| **BuildGraph** | Explicit selected-scene order, link dependencies, atlas construction, authoring metadata sizes, allocation diagnostics, and current NROM limits. | `selectedSceneEntries`, `remapBuildScenes`, `planBuild15`, `plan151`, `plan16`, `linkAssets`, preflight. | Incremental caching, new mapper allocation, world-only resource retention, generalized world execution. |
| **RuntimeCompiler** | One dispatch path for the existing packed viewer/custom, unpacked custom, and legacy single-room backends; one compiled artifact result. | `buildPacked`, `buildUnpackedCustom151`, `buildGameplay`, existing compiler/engine/package routines. | Extending Player/Target, general actor compilation, changing metadata or RAM layouts. |
| **EmulatorBridge** | Load built/original bytes, run/pause/step/reset, input release and capture requests through existing APIs. | `emuLoadRomData`, `buildAndRun`, `runImportedRom`, existing public capture methods. | CPU/PPU/APU changes, frame scheduling changes, hot reload, emulator state migration. |
| **LiveLink boundary** | An inactive capability contract: unsupported operations return a clear error without side effects. | Build artifact identity and documented future bridge interaction. | Listeners, timers, transport, ROM/RAM writes, automatic reload, incremental compilation. |

`ReleaseInfo`, a current capability model, and the docs renderer are small supporting modules, not new user-facing systems.

Keep `S` as the existing model through a compatibility view while ownership moves. It currently contains live active-scene mirrors (`nt`, attributes, palettes, CHR, OAM and tile properties), and many tools mutate those directly. **Do not create a competing second state store or an asset cache that can become stale.** Reads should use fresh indices or an explicitly invalidated index. Normalize IDs at creation/migration boundaries; registry lookup must not generate new IDs.

Serialization currently commits the active scene, reconciles metatiles and creates missing model defaults. Separate an explicit `commitActiveScene/prepareSnapshot` step from copying/encoding. Do not label a service pure while it still silently calls mutating `ensure()` functions. Build-owned data can become detached after this boundary; any remaining legacy global reads must be listed honestly.

Editor IDs and ROM addresses are different identities. The registry preserves existing project IDs; each build produces temporary index/tile/address mappings. Stable runtime asset IDs and incremental patching belong to 2.0.

**5. Concrete implementation sequence and gates**

**Step 0 — freeze and characterize.** Copy the exact current HTML into the new release's baseline directory, retain the original ZIP and every historical baseline/fixture, record hashes, and create an explicit suite manifest. Capture deterministic ROM outputs for viewer, reordered world scenes, MS16 bindings, packed custom ASM, unpacked custom ASM, and the single-room example. Add targeted tests for the reproduced storage/version/reference failures before fixing them. Gate: original 479 cases reproduce unchanged; new characterization cases demonstrate the stated failures without modifying production functions.

**Step 1 — make development sources authoritative.** Extract the current script/shell into ordered local source files and a small deterministic bundler. First prove that extraction alone reassembles the exact 1.6.6 bytes. Retain protected blocks verbatim, including their required surrounding order and closure behavior. Then make the 1.6.7 candidate from those sources. Gate: missing/duplicate inputs fail before output is written; no runtime imports, CDN, server requirement, or external example fetch is introduced. The frozen HTML becomes a comparison oracle, not the growing production patch substrate.

**Step 2 — remove fixtures and establish startup/lifecycle ownership.** Move the exact `STARTER` object to `tests/fixtures/scout166.json`. Keep normal example projects under `examples/`. Remove the production Scout branch and old default image initialization; move historical seeded data to fixtures if a test requires it. Introduce the shared blank-content factory and ProjectStore lifecycle/recovery coordinator. Fix the two save/recovery races at that boundary. Gate: blank cold start, recovery preservation, canceled/failed opens, original-save identity, replacement history, and no production fixture payload all pass.

Cold-start details are explicit: one empty scene, valid zero-filled tile/nametable/attribute/collision arrays, empty authored entities/worlds/metasprites/animations, empty assembly, no imported ROM, no undo entry, and no false saved-project identity. Retain the current cold-start **viewer** mode. Retain the existing New Project action's blank **single-room** configuration through an explicit factory option; do not silently change that established action while cleaning startup. Retain inert tracker defaults needed for a usable empty editor; no composed example music is loaded.

Recovery keeps the existing Restore/Dismiss banner. During `checking` or `pending`, autosave must not write over recovery, including on unload. A late read cannot replace edits or a newly opened project. Valid recovery stays available until explicitly restored/dismissed; invalid or unsupported recovery stays intact on rejection. Storage denial leaves a usable blank workspace and an accurate recovery-unavailable message. Blank initialization itself must not be implemented by invoking the user-facing New Project command, which creates history and replacement side effects.

**Step 3 — converge serialization, migrations and references.** Move final project schema ownership into ProjectStore; expose one serializer and an explicit migration/validation pipeline, rather than repeatedly changing `version` and delegating to older loaders. Consolidate portable ZIP sidecar registration around that same snapshot. Add AssetRegistry lookups/reference validation. Preserve unresolved world references for repair and reject duplicate identities. Route ordinary project open, ZIP project restore, recovery, clean Forge-ROM open and sync through explicit load intents. Gate: old supported projects migrate, v8 authored fields round-trip, failed validation changes no state/history/identity, and save/undo/redo preserve active edits. Retain a named legacy adapter for append-ROM reconstruction where flattening it would touch protected capture behavior.

Preserve the distinctions between those intents: ordinary full-project loading currently clears history; New Project/Open Forge ROM retain an undoable replacement boundary; history and sync loads have their own policies. A shared decoder must not make these commands identical. Likewise, ordinary project opening preserves authored assembly; the blank/clean-ROM paths may clear it as they currently do. Complete validation before any runtime pause or state replacement.

**Step 4 — converge build/preflight and execution dispatch.** Register the three existing build backends explicitly. Replace layered plan/preflight dispatch with one BuildGraph result and structured diagnostics; route global and namespace preflight aliases to it. RuntimeCompiler consumes that plan and the existing compiler/codec backends; EmulatorBridge receives only a successful artifact for Build & Run. Keep shared Save As calls at their current user-gesture boundary. Gate: golden ROM parity, one metadata/link operation per phase, no project/history mutation after snapshot preparation, and failed builds cannot run previous output.

The required build dependencies are: commit active edits; validate and select/remap scenes; derive metatile/world dependencies; construct the atlas; link metasprites/animation assets into it; encode existing metadata; assemble custom ASM or select the unchanged built-in engine so the PRG base and occupied writes are known; allocate against those writes and the current NROM reservations; pack scene/metadata/header data and serialize final CHR; optionally compile the existing single-room runtime from that linked ROM; emit the final artifact. CHR serialization must follow asset linking, and metadata allocation must follow discovery of occupied code/vector ranges. The v2 MS16 codec still contains its v1 payload. Capture these dependencies in tests, not predecessor-wrapper side effects. The single-room backend must continue suppressing the intermediate viewer download and resetting build/run mode on success and failure.

Centralize the **current** NROM profile: mapper 0 output, existing 16/32 KB PRG and 8 KB CHR limits, seven packed viewer scenes, `$D000` scene base/`$0600` stride, atlas/OAM limits, the existing metadata window and vector reservations, and the single-room `$B800` GP16 reservation. Do not relax the current requirement that world-used metatiles be represented in source-scene linkage; that needs later resource linking.

**Step 5 — consolidate documentation/identity and define the inactive LiveLink boundary.** Replace accumulated current-release docs with a capability-oriented reference generated from one source; put release history in `CHANGELOG.md`. Use ReleaseInfo for title, header, startup status, package metadata, export foundation and help. Keep separate project/codec schema numbers. Show correct viewer/custom versus single-room limits in build diagnostics. Add the inactive LiveLink capability and rejection contract without background activity. Gate: current docs have one owner, repeated navigation does not duplicate sections/listeners, no stale ready toasts appear, no false world/audio/live-edit claims appear.

The protected capture and Save As blocks contain historical docs wrappers. Preserve those bytes and hashes; the canonical current renderer must not call their accumulated docs chain. Record the retained strings as inert legacy content. Do not edit hash expectations to hide a refactor. This is a deliberate limited exception to source cleanup, while the active docs behavior still converges.

**Step 6 — verify and package.** Run all inherited behavioral cases against the candidate, plus the convergence suite; compare the known outputs against frozen 1.6.6. Rebuild twice to establish deterministic HTML, then package and re-extract the release and execute its supplied runner. Keep original historical tests runnable against their original baselines and document every intentional candidate adaptation. Run the focused browser acceptance pass when access is available; if blocked, publish the exact unverified scope and do not call it browser-verified. Gate: the packaged runner, suite manifest, measured total, hashes, source inputs, examples, and fixtures all agree.

**7. Compatibility policy**

Target project schema **v8** and the existing ROM versions for 1.6.7. Change `foundation` to 1.6.7; it is an application release identifier, not a substitute for schema capability checks. Add a schema or extension version only if implementation genuinely introduces new serialized semantics; do not add one merely for reorganized code.

| Input/output path | Required behavior |
| --- | --- |
| Supported legacy project | Use an explicit migration for each evidenced historical shape, including known unversioned legacy data. Preserve fields and IDs already present. Inventory accepted versions from fixtures; do not equate any small/coercible number with support. |
| Current v8 project/ZIP | Validate format, integer schema, extension versions, data structure and duplicate identities before commit. Retain authored worlds, cameras, events, audio, assets, and gameplay settings. |
| Malformed/future schema | Reject negative, nonnumeric, fractional or unsupported schema declarations atomically. A known unversioned legacy shape has its own path. |
| Unsupported required extension or data-bearing field | Preserve it losslessly through a declared extension mechanism or reject the open/export with a path-specific error. Do not silently drop it or lower its schema number. Do not treat benign release-name changes as incompatible. |
| Unresolved editable references | Preserve saved values for repair; report them through reference diagnostics. Building requires resolution. Duplicate identities are rejected rather than ambiguously rebound. |
| Forge ROM | Preserve current checked NFEX/MT16/WR16/MS16/GP16 readers, CRC/bounds checks, source/index remapping and retained original bytes. Put newly strict recognized-signature/version rejection in the import coordinator before the frozen codecs; unsupported outer layout must not fall through as unrelated-ROM data. |
| WR16 v1/v2 history | Keep explicit warnings when original marker/world identities were not stored; do not fabricate recoverable destination identities. |
| Other NES ROMs | Keep supported playback, import/capture and disassembly paths; do not advertise general recovery of original world/game logic. |
| Downgrade/export target | Refuse any requested target unable to represent the project. Do not implement a lossy export mode or relabel new data as an old schema. No downgrade UI is needed for 1.6.7. |
| Older released editors | Resolved, supported same-schema data should remain readable; supplied older baselines must reject newer unsupported schemas as they already do. **Unresolved world references are not safe to round-trip through 1.6.6**, whose loader drops them. Reject an explicit export targeting that incompatible path and document the limitation even though both files are v8. We cannot retroactively change an old HTML file's validation. Test exact available baselines. |

JSON/ZIP remain complete authoring backups. ROM reopening retains the existing format's capabilities and packed-index remapping; it is not promoted to a lossless container for every project field.
