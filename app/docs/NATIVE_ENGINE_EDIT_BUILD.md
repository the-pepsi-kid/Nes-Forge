# Native engine edit/build checkpoint

This is the first native-preserving project backend on the path to the next alpha. It is **not complete Zelda II reverse engineering, full translation into generic Forge gameplay, or an alpha/beta promotion**. It keeps the complete private input ROM and a supported edit recipe inside the ordinary Forge project. Build & Run applies that recipe to a copy of the source, retaining its native mapper, code, graphics, audio and other data. No-edit builds must reproduce every original byte.

## Tutorial

1. Save the current project if needed. Open **RE / DISASM → Open spatial RE workbench**, and choose the investigated `Zelda 2 - The Adventure of Link (U).nes`.
2. In **Native game edit / build**, click **Prepare native edit/build project**. The preview identifies the source and reports four location tables, 248 static editable records and four transient read-only slots. Preparation leaves the current project intact.
3. Click **Import native game as new project**. This replaces the active workspace through the ordinary project lifecycle. It retains the complete source ROM, native edit recipe, and one reference room World with initial art/pose. **Open reference room World** displays that room. It is not the assembled overworld or all scenes.
4. Use ordinary **Build & Run** before editing. Its native backend emits a byte-identical source ROM. **Run Original ROM** remains the separate original-source control.
5. Return to RE. Select **West Hyrule → Location 44**. Its initial X is 50; change X to 49. This is one native field edit and one Undo step. Build & Run now emits a ROM differing at that single native coordinate byte. Revert X to 50 or Undo to remove the change. The terrain/icon art does not move with a location record; the original engine decides how its trigger interacts with terrain and state.
6. Supported fields are native X (0–63), native Y (0–127), native scene selector (0–62) and packed entry code (0–3). These are native coordinates/codes, not normalized World-editor positions. Source Y includes the game's coordinate convention. Scene changes require a nonempty destination stream in a verified context; unresolved special destination contexts are refused. Entry codes retain native special handling and are not universally interpreted as page numbers.
7. Use **Save Project As**, then ordinary Open Project. The source and edit recipe survive reopen; build output must remain the same. Files contain the private source ROM, so retain them as your own project backups. No source ROM or generated native project is distributed with Forge.

A stale source/project preview must be prepared again. Native edit transactions preserve other project data. Reference-room art, World paint and other editor changes remain saved authoring data, but native builds refuse them until a verified native encoder exists. The build must never silently ignore such changes or run a previous successful artifact after failure. The current projection signature is an integrity/change detector, not an authenticated signature against deliberately forged project JSON.

## Reusable method and engine adapter

`NativeRecords` is a source-independent fixed-size packed-record codec. A trusted adapter declares record count, physical offsets/strides, masks, shifts and editable fields. Decoding retains source addresses; encoding writes only declared masks, preserves unknown bytes/flags and returns the exact changed offsets. It rejects overlapping masks, duplicate edits, malformed layouts, range overflow and writes to read-only fields. The same method is exercised in a fresh Forge project using unrelated authored bytes and no original ROM.

`NativeEngineFormat` supplies the Zelda-specific layout over that codec. Four physical tables each contain 63 records. The original overworld detector scans slots 61 down to 0; slot 62 is retained read-only as transient encounter state. X/Y low bits and packed scene/entry fields are editable; their neighboring return/external/travel flags are preserved. The fourth native column and all other ROM bytes remain protected by the adapter fingerprint. Recognition accepts the original engine and changes confined to these verified fields, while retaining whole-input SHA-256 identity for the actual source. This does not recognize arbitrary hacks, other revisions or other engines.

`NativeEngineProject` owns validation and encoding for the native build backend; ProjectStore owns source/recipe serialization, lifecycle and transactions; BuildGraph/RuntimeCompiler own dispatch. Ordinary generated projects keep their existing backends. Schema **13** is required because schema-12 editors would otherwise discard the native recipe while retaining the original ROM. The actual frozen schema-12 candidate is tested to refuse the newer project before mutation. Older projects migrate without activating the native backend. The existing mashup source validator accepts schemas 12 and 13 for ordinary projects and refuses native projects without an encoder. The World ROM envelope retains its format/layout and accepts source schema 13 alongside 10–12; runtime/geometry codecs and generated engine code are unchanged.

## Behavioral evidence and remaining work

Private verification runs the original bank-7 table copier and entry decoder for all 248 static locations on an independent bounded memory bus using the existing CPU instruction core. A selected four-field edit is checked against the original entry-code routine and the original return-to-overworld routine. The tested no-adjustment town return uses the changed coordinates. This establishes the stated routines/fields, not a complete route through title/save selection, quest progression, town gameplay, camera transitions or every travel flag.

Native source leads: bank 0 `$8580` scans location slots with Y mask `$7F` and X mask `$3F`; bank 7 `$CDF5` copies location data, `$CC97` extracts scene/entry/facing, and `$CCB3` begins the outside return path. Other return-offset, direction, raft, special entrance, quest/music and initialization branches remain native behavior to investigate. The pinned disassembly references and licenses remain in `NINJA_ZELDA_RE.md` / `NATIVE_RE_RESEARCH_NOTICE.md`; source labels alone are not behavioral proof.

Next acceptance: recover the complete condition/destination/spawn/camera/movement/audio/return-state contract for a real route, translate its verified behavior into reusable Forge components, and exercise those components in a fresh project without the source ROM. This backend is a preservation foundation for that work; it does not substitute for it. Collision, AI, full animation timing, combat, item/quest systems, native art/audio encoders, full connected maps and cross-engine recognition remain unfinished. Generic packed records are implemented; generic movement-mode compilation is not.
