# Native Punch-Out arena layout writer

The owner painted arena tiles in Scene 20, then Build & Run failed because the preceding release only recovered a reference view. This candidate accepts nt/attr changes on that exact source-owned Scene and writes them into original native PPU programs 1 and 2. Old already-edited project JSON loads directly; the original source and original projection baseline remain authoritative.

NativeResourceProject gains a trusted Scene-encoder registration path. The owner masks only registered nt/attr fields back to source values for its existing projection signature; every other asset/runtime field remains protected. It validates native output byte changes against each encoder's declared spans, rejects overlap with existing recipes/other encoders, and composes output with the existing bounded background writer. Source descriptor/profile/schema versions and the recipe owner are unchanged. Three recovery services now ask the native owner for that same projection signature, so adding poses/states after supported arena edits cannot launder other unsupported changes or break the native baseline.

The arena encoder maps the 256x240 view back into the two original nametables at NT1/scroll176, preserving all hidden cells. It emits bounded native literal, increment, repeated-sequence, repeated-increment and constant-fill commands. Each page retains its two native streams with 8-bit stream indices. Four pointer operands at bank12 CPU $917B/$917E/$9184/$9187 and the exclusive data area $9190–$930C are writable. The original descriptors, program3 round overlay, other 95 PPU program slots, palette data, header, all CPU/mapper/APU code, CHR and source bytes remain untouched. Commands are executed by the original C118 routine before accepting output. Unmodified arena output is byte-identical rather than recompressed.

The existing PPU source table at $8000 lists arena IDs1/2 and special overlay ID3; other bank12 command-table data ends before this arena region, and the next pointer graph starts at $9341. These spans are specific to the two verified US revisions. No free-space guess, PRG/CHR expansion, runtime replacement or unverified table relocation is used. Built ROMs are playable native outputs; keep the source-bound Forge JSON for continued editing. Recognition of a separately reopened modified ROM remains limited by the preceding exact/protected source profiles.

Checks: `python3 reviews/punch-out-arena-build-1/run_checks.py` runs the retained 90 public checks on this candidate. `node reviews/punch-out-arena-build-1/verify_build.cjs /private/rom-directory /path/to/preceding/NES_Forge_Punch_Out_Arena.html` exercises actual old Scene painting/saving, current Build & Run, original C118 through the emulator CPU/mapper/PPU bus, independent command decoding, seam/edge tiles and attribute projection, all untouched source bytes and 95 other PPU slots, old edited-save loading, Undo/Redo, save/reopen, further state recovery, background recipe composition, all 84 source Audio entries, unmodified output and unsupported/overflow refusal. The eight retained suites are not the unavailable historical full release gate. A DOM/canvas stub does not establish real browser input/listening or hardware performance.

Limits: shared layout affects all fights; runtime HUD/Mac drawing can overwrite edits, and dynamic scroll/raster/CHR behavior remains the original engine's responsibility. Layout re-encoding has 381 compressed bytes total; arbitrary dense patterns may not fit. Off-canvas attribute bits refuse. CHR pixels, palette colors, sprites/actors, Audio and gameplay modifications still need other native writers. FD/FE tile changes can alter MMC2 latch behavior and are explicitly reported. No whole-game edit parity or full fight/hardware acceptance is claimed.
