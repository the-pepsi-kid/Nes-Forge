## Specific unresolved work and blockers

1. **Pepsi has runtime observations, not a complete background decoder.** `app/tests/re-runtime-integration.cjs` already checks all 1,024 reconstructed background bytes and 32 palette bytes at observed CPU `$C0DA`. Reuse that observation and write origins as an independent comparison; still explain native source offsets and construction. Its documented title/selection/vending/sold-out states and credit changes do not establish levels, enemies, tile collision or music.
2. **HonkeyPong's title copy needs exact execution verification.** `render.oph`'s `RenderTitleScreen` uses `CPY #$FF`, increments the pointer page and does not reset Y between pages. Verify actual transfer order/length before treating `title.nam` as a linear 1,024-byte display copy. The stored file and source comments alone do not prove that interpretation.
3. **HonkeyPong has a declared header exception.** Its byte 10 is `0x10`; strict General Analysis consequently leaves generic physical-CHR recovery unsupported. The archived header source explicitly emits that byte and one 16-KiB PRG plus one 8-KiB CHR bank. A future structural graphics profile must validate its supported layout explicitly, preserving the general intake contract and original ROM bytes. Existing FamiTone2 recognition does not supply a graphics profile.
4. **A suitable A2 corpus input is still unpinned in this restored package.** Pepsi does not establish tile collision; HonkeyPong's Pong comparisons are not automatically a native metatile collision map. Select a permitted source-backed game with actual map/metatile records and collision lookup, then pin source/license, ROM, mapper and original blocked/passable behavior. Bridge Room, workshop projects and relocated derivatives remain controls or robustness cases, not extra independent engines.
