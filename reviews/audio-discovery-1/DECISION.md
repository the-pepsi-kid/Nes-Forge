# Audio Discovery ownership and scope

The milestone is a usable unknown-ROM investigation workflow in Audio. It does not broaden native decoder acceptance. A high normalized-code overlap points to a place to investigate; native catalog or canonical conversion still requires the existing validated profile contract.

REAnalysis remains the physical-container owner. Its new synchronous inspectContainer entry point invokes the same copied-input parser and frozen report semantics as ordinary analysis, without starting an unrelated WebCrypto request. Unsupported header declarations stay unavailable.

AudioDiscovery owns detached static results and code-context comparisons. It scans only the declared physical PRG region under explicit byte/site/decode budgets. Aligned code blocks, possible CPU addresses, RAM references and indexed reads remain hypotheses. Reference data stores derived signature hashes and provenance, with no supplied commercial ROM/sample payload.

RERuntime remains the sole executed-evidence collector. AudioDiscovery.capture uses its existing identity/start/stop/report interfaces and EmulatorBridge pause/step. It advances ordinary game frames under existing CPU/mapper/APU behavior. No CPU bus hooks, dispatch patches, arbitrary unknown subroutine calls, RAM edits, second emulator, second mutable project store, schema migration or compiler/runtime emitter changes are introduced.

The Audio UI keeps a static-file source separate from the current emulator ROM so unsupported mappers can still be inspected. Loading that source in the emulator is explicit. Capturing, resetting and replacing an old trace are explicit user actions; static scanning never advances a game. Pending identity cancellation is checked before arming a reset trace, and epoch/source guards prevent stale observations or source navigation. RAM origins and partial source instructions are retained without inventing full physical instruction bytes.

The byte-preservation boundary is the public Native Audio Library parent at a94252364b63f9271cec4b16ca4a4a43478002aa, HTML c3dd4d509cb0df3be1ce60404810ec6e4cc25d95d1edfbc1cda87964f4d2247e. All 101 previous suites/1,916 cases and all 269 protected test/manifest files are reconstructed and checked, with exact reviewed reversals for the narrow release/API/test-wrapper changes. All earlier preservation layers remain active.

The original NMI sound example independently exercises actual execution and semantic-lead presentation. The source-pinned DABG/FamiStudio controls probe static availability and existing recognition boundaries. Reference games and a deliberately CHR-mutated Ninja ROM are explicitly not held-out independent family-recognition evidence. No accuracy, probability or human-effort reduction is claimed.

The next decoding step is to validate dispatcher/queue semantics, pointer/table extents, control-flow and instrument timing for another source, then add a bounded decoder and compare its output against execution. The same physical-source/observed-versus-inferred boundaries should be reused for collision, scene and animation RE.
