Your first session

Start on a desktop or laptop with a mouse and keyboard. The phone exercise is optional.

  1. 01

    Begin with a blank project

    Preserve any restored work using Save Project As…, then choose New Project. The tutorial starts with your own artwork.

  2. 02

    Follow the checkpoints

    Draw terrain and a tiny character, assemble a two-screen World, then use Build & Run. Keep the app and tutorial visible together.

  3. 03

    Save and prove recovery

    Use Save Project As… for native JSON checkpoints. Confirm the file exists, reopen it with Open Project, and build again. Keep the generated .nes too.

  4. 04

    Optional: try the phone

    Load your ROM in EMULATOR, choose Run and Play view, then test touch and interruptions. Record the phone, browser, ROM, and any lag. Mark this check “Not tested” if you skip it.

The workshop lives in the documentation and is performed in the normal NES Forge application. Browser Save stores a local browser copy; your portable JSON checkpoint is the backup to keep. The first tutorial ROM is deliberately silent, so use a ROM with known sound for audio testing.

Before you explore

  • Keep a portable project backup. Save native JSON and confirm the file exists. A generated ROM or diagnostic report cannot replace your editable project.
  • Check that exports really arrive. Source Workspace can say “Export requested” even when a save is busy or fails. Confirm the file before reporting success.
  • Audio and device tests are optional. The first tutorial ROM is silent. Use a ROM with known sound for audio testing, and record the device and browser you used.
  • Recovery has a defined scope. Source intake and ROM recovery support limited profiles. They do not promise to recover or rebuild every NES game.

Use the feedback template to record the exact step, expected result and actual result. Submit it through GitHub Issues, or return it through the channel that supplied the kit. GitHub issues are public; nothing is submitted automatically.
