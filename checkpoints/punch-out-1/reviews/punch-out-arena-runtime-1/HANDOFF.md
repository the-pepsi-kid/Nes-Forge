# Punch-Out live background bank correction

The owner confirmed that arena edits appeared in the rebuilt game, but the HUD, audience and ring displayed Little Mac patterns. Running the untouched original ROM in the preceding player reproduced the same image. The original native writer, protected ROM bytes and imported Scene data were not the cause of this reproduced defect.

Only `app/src/services/mmc2-emulator.js` changes among 168 preceding application inputs. Its visible-width background loop skipped one or two pattern fetches at the right edge, depending on fine X. The native arena places an MMC2 latch tile there; missing it left the upper pattern-table latch selecting Little Mac's FE bank while rendering the next row's HUD. The corrected loop fetches 34 background pattern rows, preserving both bitplane reads and mapper side effects, and clips only the output pixels. Background fetches also run when sprites alone enable rendering; all rendering disabled leaves latches unchanged. Other mappers still delegate to their previous renderer. CHR banking tables, read-before-latch behavior, sprite rendering, CPU/APU timing and source codecs are unchanged.

Verification:

- `python3 reviews/punch-out-arena-runtime-1/run_checks.py`: eight retained suites (90 checks) plus 14 synthetic fetch checks, including fine X 0–7, FD/FE transitions, no accidental 35th fetch, sprite-only/disabled rendering and read-before-latch.
- `node reviews/punch-out-arena-runtime-1/verify_runtime.cjs /private/roms /path/to/NES_Forge_Punch_Out_Arena_Build.html`: boot each untouched US revision for 1,250 native frames with controller Start intervals; copy the identical native RAM/nametable/OAM/palette/CHR/scroll state into preceding and corrected players. Independently compare HUD pixels with source bank 0. Each revision reproduces 11,501 incorrect pixels before correction and zero afterward over 14,336 sampled pixels. No source-state/pixel payload is stored in this checkpoint.
- `node reviews/punch-out-arena-runtime-1/verify_build.cjs /private/roms /path/to/NES_Forge_Punch_Out_Arena.html`: actual Scene paint/saved edits, native Build & Run and original PPU loader through the emulator CPU/mapper/PPU bus; unchanged protected bytes and other source programs; save/reopen, Undo/Redo, further state recovery, native background recipe composition, Audio84 and unsupported/overflow refusal.

Private full-frame renders were inspected before/after; source screenshots, ROMs and decoded art are excluded. The correction does not establish cycle-accurate PPU sprite evaluation/prefetch ordering, full raster timing, all fight states, browser listening or hardware acceptance. MMC2 runtime capture remains explicitly unavailable. Native arena compressed capacity remains 381 bytes; source/writer/project ownership and schemas are unchanged. Keep the Forge JSON for continued editing of the preserved source.

Primary technical references: https://www.nesdev.org/wiki/PPU_rendering (background fetches at dots321–336 and1–256) and https://www.nesdev.org/wiki/MMC2 (pattern-read latches). The observed regression and pixel counts above come from supplied-ROM tests, not those documents.
